# Failure Atlas

Every real-world pattern HubbleOps has met and how it was handled. Fed by the
[real-repo loop](../prompts/cross-cutting/real-repo-loop.md) from the Phase 2 gate onward, and by
[Phase 10](../prompts/phases/10-pilot-hardening.md) pilot hardening.

Rules:

- No customer identifiers. Anonymize the pattern; keep the shape.
- One row per pattern, added the moment it is found — not at the end of a phase.
- A pattern that is genuinely undecidable statically gets `PRESERVED UNKNOWN` in *Disposition* and a
  precise closing instruction. That is a correct outcome, not a gap.
- No rule tuned to a single repo's names. If it can't generalize, it's a fixture, not a rule.

| FA-014 | Git refuses to remove its own worktree metadata because the directory carries the read-only attribute, so a capture leaves state inside a repository it promised not to modify. | Any language | Phase 4 real-repo loop | Detached worktree lifecycle | 4 | `test_a_worktree_whose_removal_is_refused_still_restores_the_repository` | CLOSED_WITH_EVIDENCE; removal retries, then clears the read-only attribute and prunes, and the lifecycle still fails closed if the metadata does not return to its prior state. The attestation records `recovered`. Observed on both pinned repositories, so the recovery path is load-bearing, not incidental. |
| FA-015 | A test command that fetches dependencies at run time makes the workload's package manager attempt egress, which the deny-all proxy correctly observes and denies; the request is not provider traffic, so it becomes `UNKNOWN_WIRE_SIGNATURE` and one UNKNOWN candidate per unclassifiable request. | Any language, proxy mode | Phase 4 real-repo loop | Wire signature classification | 4 / 5 | none — behaviour is correct | PRESERVED UNKNOWN; the reason names the exact target so a human can dismiss it. Dismissing non-provider hosts automatically is **rejected for now**: an incomplete pack host list would then hide real usage, which is the failure the laws exist to prevent. Revisit only if a real suite's unclassifiable egress swamps its ledger. |
| FA-016 | Every source path is passed on one command line, so beyond roughly 500-800 files the operating system refuses to start the analyzer and the failure is reported as a missing tool that is in fact installed and working. | Any language | Post-Phase-4 stress measurement | `graph/imports.py` argument batching | 4 | `test_query_invocations_track_batches_not_file_count` | CLOSED_WITH_EVIDENCE; paths are batched under a 24,000 character budget against the 32,767 character Windows `CreateProcess` limit, and a refused start with the executable present is now `TOOLING_FAILED` naming the argument length, never `TOOLING_MISSING`. Measured: 800 files failed before, 4,000 files pass after. |
| FA-017 | An enumerator and a searcher walk the same tree with independently maintained exclusion rules, so a directory pruned from the closure is still reached by the search and the run fails closed on a path the closure never enumerated. | Any language | Post-Phase-4 hardening | Source Closure exclusion surface | 4 | `test_the_searcher_never_reaches_a_directory_the_closure_did_not_enumerate` | CLOSED_WITH_EVIDENCE; `SourceClosure.search_exclusions()` is the single source of truth and ripgrep derives its globs from it. Two hand-maintained lists of the same invariant is a defect with a delay, not a style choice. |
| FA-018 | Wrapper-walk lookups scan every match in the repository and filter by path, so analysis cost grows with the product of candidates and repository size rather than with the file being analysed. | Any language | Post-Phase-4 profiling | Import graph path indexes | 4 | `test_the_graph_answers_path_lookups_without_scanning_the_repository` | CLOSED_WITH_EVIDENCE; the graph builds path and id indexes once, and `SourceRange.contains` fell out of the top twelve profile entries.
